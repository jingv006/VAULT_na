# VAULT 收纳工作台

网站制作：**@液体香胶**

浏览器里的二维收纳柜搭建工具，基于同级 `261021_VAULT_USSA_S` 模型库。原始模型保留在原目录，不复制、不上传。

## 开始使用

Mac 上双击项目根目录的 `打开VAULT工作台.command`，或本目录的 `启动工作台.command`，会自动启动后台服务并打开工作台。可以关闭启动时的终端窗口，服务继续运行；再次双击会复用已有服务，不会重复启动。优先使用 <http://127.0.0.1:8766/workbench.html>，端口被其他项目占用时自动选择空闲端口，不会关闭其他项目。方案保存在对应地址的浏览器中，重要方案建议另存 JSON。启动日志位于 `tmp/launcher/server.log`。

也可以在本项目目录运行：

```sh
python3 server.py --port 8765 --open
```

基础网页和 ZIP 功能使用 Python 3.9+ 标准库；3MF 与三维网格转换使用本机已安装的 NumPy。三维预览的网格简化库已随本地项目保存在 tools/vendor（当前 Mac / Python 3.9）；浏览器 Three.js 也已本地保存，无需联网加载。本机服务器只监听 127.0.0.1。

在线版提供相同界面；打包前点击“连接模型文件夹”，选择原始模型库。浏览器只在本机读取文件，不向服务器上传 STL。在线版建议使用 Chrome / Edge，以支持将大 ZIP 直接写入磁盘；不支持直接写磁盘的浏览器限 400MB。超过约 3.9GB 的方案请使用本机版，后者支持 ZIP64。

## 操作

- 左侧筛选抽屉柜、翻盖箱、宽度、高度和深度。拖动卡片进入画布，或点击加号。
- 正面视图中拖动模块，默认开启强吸附，横向必须落在边缘对齐槽位，纵向自动贴合层位。拖到现有模块的下半部/上半部，会插入该模块下方/上方；受影响的上层模块自动上移，移出位置的上层模块自动落下补齐，独立列不受影响。橙色插入线预览目标位置；不能完整支撑上方模块的插入会保持原位；关闭“强吸附”恢复自由摆放。一次拖动可整体撤销，按 Escape 或取消拖动可恢复原布局。点击空白处拖动平移，底部可缩放和适应画布。
- 点击模块编辑坐标、高度、顶盖、Gridfinity 底板、加强齿条和预览颜色。按 Delete 删除，方向键移动，Shift 加方向键移动 10mm。
- 可撤销/重做、查看俯视占地、导出 SVG、保存/导入方案 JSON。方案自动保存在当前浏览器 localStorage，不跨浏览器同步。
- 配件库可追加任意原始配件；清单可手动修改 STL 打印份数。橙色边框表示手动覆盖，恢复配方数量可取消覆盖。手动覆盖数量固定，不随后续模块增删而变化。
- “合并同名模型”每种文件保留一份，`print-N` 是所需打印份数。“按打印数量复制”会在压缩包中生成 N 份文件，适合切片导入。
- ZIP 保留原始目录层级，包含 STL、CSV 清单、方案 JSON、SVG 预览及紧固件清单。本机版同时包含原始 PDF；在线版附带所选择文件夹内匹配的 PDF。

## 模型与配方

已索引 733 个 STL，建立 160 个模块配方：70 个抽屉柜（含双抽屉柜体）和 90 个翻盖箱。原始文件名中的大小写、空格差异在索引时处理，导出使用原始路径。

配方参照本地原版 `01_Instructions Manual.pdf`、`02_Drawer Assembly.pdf` 及命名图，数量单位为 **STL 文件打印份数**。例如 Springs 文件包含一对弹簧，不能将“份数”误作独立零件个数。可选分隔板、手柄、脚座、支架等从配件库添加；改装配件额外五金按原说明另计。自动配方仍需在实际切片/装配前核对，网页允许修正各项数量。

抽屉柜的顶盖仅在整块模块上方没有其他模块时自动加入，避免每层重复计顶盖；翻盖箱每个模块始终包含其翻盖。若更高处有悬空模块，当前计算也会将其下方模块视为被覆盖，因此先处理悬空提示再核对顶盖。

S/M/L/XL 名义宽度为 164.8/254/329.6/418.8 mm，按 L=S+S、XL=S+M 用于拼接规划；实际网格有少量制造差异。深度为 42mm 格距，1F 高度为 48mm 堆叠节距。这些不是带凸起/锁扣/顶盖的最大外形尺寸。二维检查只检测矩形重叠、底部完整支撑和上下层深度差异；不验证三维干涉、连接方式、公差或承重。

导出文件缓存在 `exports/`，后续新建导出任务时清理超过一天的导出缓存。不会删除原始模型。

## 文件结构

- `dist/`：可独立部署的静态网页、核心运算与流式 ZIP 导出器。
- `dist/catalog.json`：实际模型索引和完整模块配方。
- `server.py`：本机模型连接、分块读取和 ZIP64 打包。
- `tools/build_catalog.py`：重新扫描原始库、重建索引；运行需要 Python 3，无第三方依赖。
- `tools/verify.mjs`：配方路径、混搭支撑、重复用量、导入校验、ZIP 内容的关键回归检查。

网页无构建步骤。若改变模型库或配方，运行 `python3 tools/build_catalog.py`，然后重启服务。

## H2D 耗材与时间预估

工作台通过 `dist/estimates.json` 读取逐 STL 的实际切片统计。统一采用 **Bambu Lab H2D、0.4mm、0.20mm、Bambu PLA Basic、15% 网格填充、2层墙、5层顶、3层底、无自动支撑、自动裙边5mm设置**。每条记录包含源文件 SHA-256、参数指纹、克重、线长、预计时间、层数和切片状态，避免把网格体积直接当成耗材。

主页面按完整打印清单的实际份数汇总，自动处理顶盖、配件和手动数量覆盖。CSV 与 ZIP 也会保存每份用量、每项总量和切片参数。尚未得到结果的模型不会计作零；页面以“≥ / 已知部分”和缺失数量说明覆盖范围。

时间是每个 STL 单独切片的预计总时间乘以打印份数后累加，包含单份切片器计入的准备开销，不等同于合盘优化后的实耗时间，也不代表多台打印机并行后的完成时间。合盘通常会减少重复准备开销。

文件名标明需开启支撑的模型，当前统计仍按统一的“无自动支撑”基准，额外支撑需另计。`Tyre (TPU)` 等专用件也会提示当前是 PLA 基准，不能以此替代实际材料的切片。

H2D 标准有效范围无法容纳的整件，允许用 **600mm 虚拟范围**补做统计，保留同样的模型尺寸、方向、挤出和 H2D 速度设置，单独标记 `estimateOnly` 和 `printableOnH2D: false`。该记录仅用于估算，不代表可以在 H2D 整件打印；应选择已有分件、重新拆分或换机。批量统计完成后只保留结果与日志，不保留这些估算用 G-code。

批量任务可断点续跑：

```sh
python3 tools/batch_slice.py --workers 2 --retry-failed
```

切片器使用本机安装的 OrcaSlicer 2.4.2 和其 H2D 官方预设。Bambu Studio 批量接口在本机出现线程死锁，最初试跑数据另保存在 `slicing/H2D-PLA-020-15pct-2walls/` 供核对，系统采用统一的 OrcaSlicer 批处理记录。全库 CSV、配置和逐文件结果位于 `slicing/H2D-PLA-020-15pct-2walls-orca/`。

本次全库已完成：733 个 STL 均有记录，608 个在标准 H2D 当前方向范围内切片成功，125 个采用虚拟范围补做估算。其中4个XL分件底板在当前方向下含悬空结构，单独开启了自动支撑，其耗材与时间已包含支撑；其余维持默认无自动支撑。完整结果见 `slicing/H2D-PLA-020-15pct-2walls-orca/all-model-estimates.csv` 与同目录的 `批量切片结果.md`。

## 中文部件名与打印机尺寸检查

配件卡片、打印清单和 CSV 用中文显示部件名称，仍保留原文件名与原始路径；ZIP 中的模型文件和目录不改名。中英文均可搜索，S/M/L/XL、深度编号和 F 高度代码保留用于对照原模型。

网页的“哪些机器放得下？”按当前打印清单中的每个 STL 实际外形判断，包含配件、手动数量、露出顶盖和分件配方。堆叠柜整体的尺寸不作为单次打印尺寸。选择机器后画布标出受限模块，下方列出具体零件、外形尺寸、份数；三品牌机型对照随方案更新。CSV 与 ZIP 的耗材时间 JSON 同时记录选择的机器、尺寸和检查结果。

`dist/printers.json` 收录截至 **2026-10-24** 核对的拓竹、创想三维、纵维立方共 **24款机器 / 27种模式**，每条都保留官方产品页或说明书来源。H2D、H2C、X2D 分开列出单/双喷嘴有效区域；H2D单喷嘴采用325×320×325mm，共同双喷嘴区域300×320×325mm，不把两喷嘴合计350mm宽度当成单件范围。机型选择仅改变尺寸筛查，耗材与时间仍统一沿用H2D切片基准，不会冒充其他机器的切片时间。

默认检查原方向和平面90°旋转；允许换面时额外检查六种轴对齐方向。可设置热床每边0/3/5mm预留（只影响XY，Z不预留）。“当前放不下”表示所检查方向的包围盒超界，不是证明所有斜放角度都不能打印；需要时在切片器调整方向或拆分。实际支撑、裙边、擦嘴、校准、禁入区和工具头限制仍需切片器确认，尺寸内不等于已完成可打印性验证。换面也可能改变支撑需求和耗材、时间。

全部733个STL的实际顶点包围盒保存在 `dist/geometry.json`，与名义柜体尺寸分开。源模型不修改。更换模型后运行 `python3 tools/build_geometry.py` 重建（工具需要numpy；只有重建需要，正常启动仍只需Python标准库），随后刷新网页。运行 `tools/verify-printers.mjs` 可验证全库尺寸覆盖、翻译和各配方的机型检查。

## 尺寸总览与预分色 3MF

启动后的首页现为 **箱子与文件总览**；原二维堆叠工具位于 `workbench.html`，原有浏览器方案继续保留。首页可按S/M/L/XL、3–7格深度、1/2/4层筛选160种完整模块，搜索 `S3F1` 或 `S3 1F`，查看中文部件、原STL路径、份数、参考颜色和用量；切换顶盖、底板、齿条后，清单与下载内容同步。可将选中箱子加入原堆叠方案，支持撤销。

参考配色从本地官方文档核对：`01_Instructions Manual.pdf` 的 Important Notes 明确主色为 Bambu PLA 浅灰10104，抽屉与翻盖箱爆炸图、`02_Drawer Assembly.pdf` 的装配图提供深灰内件、橙色功能件和浅色标签的分工。深灰、橙色和标签未找到官方明确色号，因此页面色值标为近似预览。用户可修改四个材料槽的颜色。原始STL和PDF不修改。

每个3MF按所需STL打印份数展开为独立、中文命名的对象；同色零件分盘，只平移与平面90度旋转，不缩放。工程保存标准3MF材质颜色、Bambu Studio材料槽、分盘信息、H2D/0.4mm/0.20mm/15%网格填充/2层墙配置，以及 `Metadata/vault_manifest.json` 和中文CSV。原文件已标明需支撑的对象会预设启用支撑，4个特殊XL分件也会启用；网页耗材时间仍沿用原切片基准，新增支撑另计。切片软件打开后需核对实际支撑、摆放、禁入区和材料槽映射；工程不包含已切片G-code。当前方向超界的部件保留原尺寸，单独标记，避免静默缩小。

首次点击下载会在本机整理网格，页面显示进度，完成后自动下载；相同型号与选项再次下载直接读取缓存。不会预先重复转换160份的大模型。网格缓存按源路径、大小和修改时间复用，3MF缓存按型号、选项、颜色和源文件版本区分。生成3MF需要本机numpy（当前环境已具备），正常网页和原ZIP功能仍用Python标准库。

- `dist/palette.json`：依据与角色配色规则；参考页缩略图位于 `dist/references/`。
- `dist/kits-index.json`、`dist/全部箱子文件索引.csv`：160种默认完整配方，共2142行文件用量。
- `kits/按尺寸整理/抽屉柜或翻盖箱/尺寸代号/款式/`：每种箱子的文件清单、配方与配色JSON、所需STL的本地符号链接。链接复用原模型；它们的 `print-N` 表示该文件的打印份数。已生成的默认3MF也会链接在相应目录。

目录缩略图仍用 `dist/kit-preview.mjs` 按型号的名义尺寸绘制。大预览可切换二维示意与 Three.js 三维视图；三维使用对应配方的真实 STL 显示网格，支持旋转、缩放、平移、爆炸程度滑杆、抽屉拉出、翻盖打开、视角复位和全屏。四个材料槽的颜色在预览旁自由修改，实时更新网格、缩略图、清单及下载的 3MF，并在本机浏览器记住。恢复参考配色可清除配色记录。


## 真实 STL 三维预览

`preview_service.py` 按完整配方读取原始零件，在本机调用 `tools/build_preview_assets.py`，进行精度居中、显示网格简化和零件打印姿态旋转，缓存到 `dist/preview-assets/`。首次选择新型号或新配件时显示逐件进度；重复选择复用缓存。3MF 导出继续使用原始无损网格，显示简化不影响打印文件、耗材或时间统计。缓存依据源路径、大小、修改时间和转换版本区分。

装配位置采用按部件用途和实际外形尺寸编写的展示规则；原库没有提供装配坐标或关节文件，因此这些位置不是经 CAD 配合关系求解的精确装配。抽屉、面板和滑轨联动移动，盖子围绕后侧轴打开；爆炸图用于分辨零件关系。铰链、锁扣、密封隔板和特殊分件的位置仍是展示近似，不用它检查公差、碰撞或装配可行性，实装应对照原版文档。

`dist/assembly-viewer.mjs` 为三维控制器；`dist/vendor/three/` 内保存 Three.js 0.180.0 与 MIT 许可；`tools/vendor/` 内保存 fast-simplification 0.1.12 及许可。普通查看无联网请求。若搬到不同系统或 Python 版本，可用相应 Python 安装 `numpy` 与 `fast-simplification==0.1.12`，或使用原电脑已生成的显示缓存。

三维检查：`node tools/verify-assembly.mjs` 核验五个已缓存的代表型号（标准抽屉、翻盖箱、左右双抽屉、密封分隔箱、4F 高抽屉），包含完整三角索引、二进制边界、各部件数量、双抽屉左右分配、开合方向、爆炸位移和材料颜色。浏览器另核对旋转、开合、爆炸、实时改色与 3MF 配色保持。


### 抽屉装配对齐修正（2026-10-26）

`tools/preview_landmarks.py` 在显示网格简化前测量源 STL 的主要平面和面板圆孔；全部 10 种抽屉面板的孔中心、半径和端盖数量保存在 `tools/facade-datums.json`，可用 `python3 tools/measure_facades.py` 重新测量。`dist/drawer-alignment.mjs` 依据实测柜体内底面、外顶面、面板背面、圆孔和轴端面定位，替代按高度百分比估算。

已核对顶盖接触面、抽屉底部 0.2 mm 展示间隙、面板与抽屉前缘贴合、旋钮与帽的同轴和插接、端盖孔中心、标签凹槽、左右弹簧卡槽与导轨朝向。加强齿条改为抽屉前缘上下横向摆放；左右不等宽的 S+M 双抽屉按各自的实测孔数分配端盖。源 STL 的打印方向、原始网格和公差不修改。翻盖箱现采用独立的实测装配规则；未作 CAD 约束或物理干涉求解。

端盖清单随源面板实测修正：S 的 1F/2F/4F 为 1/3/3 只；M 和 L 的 1F/2F/4F 为 3/5/5 只；XL 1F 为 3 只。双抽屉分别相加。网页清单、耗材与时间汇总、CSV、3MF 和按尺寸整理目录使用同一数量；失效的旧生成链接会清理，原始模型不删除。3MF 与三维任务缓存键包含份数，防止配方数量改变后读取旧缓存。

### 爆炸动作、插销、旋钮帽与渲染细节修正

## 组合模块整合 3MF 打包

打包弹窗第一项保留原有 STL 合并方式；第二项改为“按模块输出整合 3MF”。同型号、有效顶盖与配件选项的模块归并成一份单套工程，文件名 `__print-N.3mf` 表示整份工程需打印 N 套，不在工程里重复放 N 套。不同顶盖或网格/齿条配置分别输出，被上层覆盖的抽屉不含顶盖。使用与尺寸总览同步的自定义配色，浅色预览不影响生产配色。

备用件仍以独立 STL 附带并用 `print-N` 标注数量；压缩包另附模块套数清单、完整零件清单、方案、预览、估算和原版装配说明。完整 3MF 配方与手动修改的零件数量不一致时会明确提示使用第一项或恢复配方，不静默忽略修改。整合 3MF 生成沿用本机服务，浏览器目录模式保留第一项。

验证：`node tools/verify-module-export.mjs` 后运行 `python3 tools/verify-module-export.py`。覆盖 3 套相同配方只生成一份 `print-3` 工程、被覆盖顶盖分组、配件/翻盖/双抽屉/XL、JS 与服务端 BOM 一致性，以及真实 3MF 的单套网格数量、配色、打印参数和 ZIP 完整性；原 STL 合并方式逐字节保持一致。
